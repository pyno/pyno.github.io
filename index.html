RESEARCH

Raiders of the Lost Firmware: A Hands-On Workshop in IoT Firmware Archaeology

DEFCON 34 - IoT Village

Modern IoT firmware is often protected by proprietary encryption that blocks traditional analysis. This hands-on workshop focuses on firmware archaeology, a practical methodology for reconstructing firmware decryption schemes using artifacts from firmware archives, public repositories, and developer ecosystems. Attendees will analyze a real commercial IP camera platform, recover cryptographic routines from binaries, and emulate vendor functions to decrypt protected firmware without reimplementing the cryptography. They will then explore hidden functionality and map the platform’s broader attack surface. Through practical exercises and pre-packaged tooling, participants will learn a repeatable approach for overcoming firmware analysis barriers across modern IoT platforms.

On TLS 1.3 — Early performance analysis in the IoT field

ICISSP

This paper provides an overview of the novelties introduced in TLS 1.3 draft finalized to improve security and latency of the protocol: the reworked handshake flows and the newly adopted cryptographic algorithms are analyzed and compared in terms of security and latency to the current TLS in use.

What users should know about Full Disk Encryption based on LUKS

CANS

Full Disk Encryption (FDE) solutions might help users to protect sensitive data in the event that devices are lost or stolen. In this paper we focus on the security of Linux Unified Key Setup (LUKS) specifications, the most common FDE solution implemented in Linux based operating systems. In particular, we analyze the key management process used to compute and store the encryption key, and the solution adopted to mitigate the problem of brute force attacks based on weak user passwords. Our testing activities show some weaknesses and user’s behavior that can significantly reduce the security of the main LUKS implementation, Cryptsetup.

On the weaknesses of PBKDF2

CANS

This paper shows that, if HMAC-SHA-1 is computed in a standard mode without following the performance improvements described in the implementation note of RFC 2104 and FIPS 198-1, an attacker is able to avoid 50% of PBKDF2’s CPU-intensive operations by replacing them with precomputed values. We note that a number of well-known and widely used crypto libraries are subject to this vulnerability. In addition, we describe other minor optimizations that an attacker can exploit to reduce the key-derivation time even further.
